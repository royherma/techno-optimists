# Decisions archive (through 2026-09-11)

History, not rules. These rows record what was decided and why, including decisions
later reversed by other rows in the same table. Do not read this file to learn how the
system behaves - read the code.

The subset that is still true of the code, and still worth reading before a deploy or a
schema change, was moved to `docs/CONSTRAINTS.md`. Nothing is appended here any more.

One row per decision. Newest at the bottom.

| 2026-09-10 | Tailwind arbitrary vars use `bg-(--token)`, never `bg-[--token]` | v4.1 dropped the bare shorthand: it compiles to invalid `background-color:--token` and browsers discard it silently. `@theme static` so tokens used only from inline styles survive tree-shaking |
| 2026-09-10 | Seed imagery is generated SVG, not stock photos | Photo IDs written from memory did not match their captions. Local art is free, offline, and provably correct |
| 2026-09-10 | The index is drawn as a survey sheet: neatline, title block, margin graticule, scale bar, north arrow | The reference design's whole argument is that the page is an object with edges. Without the furniture it reads as a feed with a border |
| 2026-09-10 | Contour rings carry the stage colour, ring count carries impact | Black rings spent a channel on nothing. Count says how far a Challenge reaches, colour says what is being done about it - one glance, two facts |
| 2026-09-10 | The legend shows every tier, never a sample | A legend listing 3 of 5 ring tiers leaves the reader guessing at the two it skipped, which is the one thing a legend exists to prevent |
| 2026-09-10 | Action glyphs are taught once in the legend, then used unlabelled on every row | Symbols survive translation and cost one glance instead of a sentence. This is the payoff for having a legend at all |
| 2026-09-10 | Rules between grid columns go on the stretched grid item, never on a sticky inner box | A border on a sticky element stops where its content stops, leaving the bottom of a long sheet unruled |
| 2026-09-10 | A missing media object drops the `<img>` and keeps the tinted plate | The box is already the right shape and colour, so a dead R2 key reads as intentional rather than as a broken page |
| 2026-09-10 | Static pages are the fast path; a Challenge posted since the last build is filled in client-side from `window.__LIVE_CHALLENGE__` | `output: 'static'` prerenders only what existed at build time, so fresh Challenges 404. Serving an existing page as the shell keeps one template instead of a second that drifts |
| 2026-09-10 | The action bar fetches its own Challenge rather than reading props | A DOM `setAttribute` cannot reach a mounted React island, so the bar showed the shell's type and counts |
| 2026-09-10 | Email is stored in `identities`, never on `people` | A `SELECT p.*` on the person table can then never leak an address into an API response |
| 2026-09-10 | Sign-in links carry `?next=`, and acting while signed out returns to the Challenge | Asking for a sign-in at the moment of contribution only works if the reader lands back where they were |
| 2026-09-10 | Capture and sign-in render inside the same `Sheet` as the index | They are pages of one document. A bare card on the graph paper reads as a different site |
| 2026-09-10 | `dev_link` is returned only when `ENVIRONMENT !== 'prod'`; prod fails closed | The magic link is a bearer token. Returned unconditionally, POSTing a stranger's address hands over their account. A missing mail key in prod must break sign-in loudly, never open a door |
| 2026-09-10 | Deploying dev is two steps: `db:reset:dev` then `deploy:dev`, whenever the schema moved | `schema.sql` shipped `identities`/`magic_links`/`sessions` after the last dev reset, so live sign-in 500'd on `no such table: magic_links` while every local test passed |
| 2026-09-10 | The build prerenders from LOCAL D1, so local test rows ship to whatever the Worker serves | Eight throwaway rows ("...dry season 1353", "Testing whether a fresh Challenge renders") were linked from the deployed front page and returned 200. Keep local D1 equal to the target DB before `deploy:dev`, or the index advertises Challenges the API does not have |
| 2026-09-10 | Never write HTML entities in `.astro` markup - use the character (`-`, `←`) | Astro escapes them, so `&mdash;` and `&larr;` reached users as literal text in the title block, the footer, the legend and every back link |
| 2026-09-10 | No prod deploy until a domain is bought. Dev/staging is the only target | A verified sending domain unblocked email, which is not the same as unblocking a launch. `workers.dev` is not a URL to put in front of users, and shipping there quietly makes it the address people bookmark |
| 2026-09-10 | Prod D1 `techno-optimists` holds the 7-table schema AND the 12 seed rows | Applied while prod was briefly un-parked, then called off mid-sequence. The DB is not the untouched empty one the config comment describes. No Worker, no secrets, nothing deployed - the data is unreachable, but it is there and a later `db:prod` would drop and rebuild it |
| 2026-09-10 | `Media` carries `w`/`h`, recorded at upload; no surface hardcodes an aspect ratio | Without dimensions every surface guessed a ratio and `object-cover` cropped the rest. Seed art is uniformly 1200x900, which hid it completely - measured against a 9:16 portrait, a 32:9 panorama and an 8x8 sprite, all three rendered at 1.34 |
| 2026-09-10 | Reverses row 18 in part: the spec panel, scale bar and north arrow are gone; neatline, graticule and title block stay | The sheet has no projection, datum or scale - `vocab.ts` says the grid reference is an index derived from an id, not a position. `GRID 1000 m` / `PROJECTION LOCAL TM` / `1:250,000` described measurements that do not exist, so the furniture read as authority while carrying none. Row 18's argument holds for the edges, not for invented values |
| 2026-09-10 | `contain` plates take the media's true ratio; only `cover` plates clamp | A clamped frame plus a contained image means frame and picture disagree, and the gap renders as empty tint - a 9:16 hero in a 2.6-wide box was ~60% letterbox. Bound contained media by max-height so the plate shrinks instead of padding |
| 2026-09-10 | Below sm a Challenge row is flow layout, not the five-column table | Cells placed by `col-start`/`row-start` into a grid that cannot hold five columns at 390px scattered one row into a zigzag - number top-left, rings floating right, stage stranded at the bottom. The table starts at sm, where the widths exist |
| 2026-09-10 | The legend is a `<details>`, closed on a phone and forced open from lg | Open it runs 823px, so a reader met a full screen of apparatus before the first Challenge; last on the page it landed at 4254px, after everything it explains. Neither end of the page is the answer. `open` ships in the markup so it works without JS; only the phone needs it shut, and no media query can remove an attribute |
| 2026-09-10 | `order` classes are never the only thing placing an element | `lg:order-1`/`lg:order-2` on a wrapper that is `lg:grid` do nothing below lg, where the container is a plain block - the legend stayed last on mobile while the code read as if it had moved. Source order carries the mobile case; `order` only rearranges what the grid already holds |
| 2026-09-10 | The detail h1 starts at 1.75rem and steps up at sm/lg | A flat 2.4rem set a real title over six lines at 390px, filling the whole first viewport before the summary. The display face still leads the page, at a size the phone has room for |
| 2026-09-10 | `@handle` is the only public identity; `people.name` is returned by `/api/auth/me` alone | `name` is derived from the email local part at signup, so `roy.herma@gmail.com` becomes "Roy Herma" - a real name nobody chose to publish, printed under every Challenge, progress-log entry and helper. Removing it from the three SQL selects as well as the markup means it cannot reach a response by someone forgetting to omit it, the same argument as row 26 for email. `PublicPerson = Omit<Person,'name'>` names the safe shape once |
| 2026-09-10 | A `404.astro` exists so the Worker has something to serve on a miss | `output: 'static'` emits no 404 page unless the file exists, so `ASSETS.fetch` answered a mistyped `/c/<slug>` with a bare empty body. The status was right the whole time - there was simply nothing to show, which reads as a broken site rather than a wrong link |
| 2026-09-10 | Every truncating cell carries `min-w-0` on the flex parent as well as the child | `truncate` is inert without a bounded width. A flex item defaults to `min-width:auto` and refuses to shrink below its content, so a 120-character location pushed the row off a phone instead of ending in an ellipsis. The child class alone never fixes this |
| 2026-09-10 | `db:seed:*` regenerates `seed.sql` before loading it; the file is never hand-edited | `gen-seed.mjs` gained `w`/`h` but nothing regenerated its output, so `seed.sql` still carried dimensionless media and `db:reset:dev` faithfully reseeded the stale SQL. The media-sizing work was live and inert - every plate fell back to a guessed ratio because all 12 rows shipped without dimensions. A generated file with no script generating it is a file that silently lies |
| 2026-09-10 | `technooptimists.org` bought; prod un-parked and bound to the apex + `www` as custom domains, `workers_dev: false` | Reverses row 33, which held only until a domain existed. Custom domains in `wrangler.jsonc` mean the deploy writes the DNS itself - the OAuth token reads `zone` but 10000s on `dns_records`, and never needed it. Leaving `workers.dev` on would publish a second address for one site, and the one people bookmark is not a choice worth leaving to chance |
| 2026-09-10 | Prod D1 ships empty - schema only, no seed - and local D1 is emptied before `deploy:prod` | The 12 seed Challenges ("well-pump-runs-dry", "milk-cooling-loss") were already in prod D1 from the aborted un-park, and the build prerenders from LOCAL D1 (row 31). Either one alone puts invented problems on a public domain under real people's names; the front page would have advertised 12 Challenges with 0 identities behind them |
| 2026-09-10 | Prod D1 has no migration path: `db:prod` only runs `schema.sql`'s bare `CREATE TABLE`s, so a new column never reaches an existing database | `fffbd5f` added `identities.is_admin` to `schema.sql` and to the signup INSERT, and shipped. Prod D1 predated it, so the column was only ever in source: the first real sign-in hit `INSERT INTO identities (person_id, email, is_admin)` against a 4-column table and D1 threw `no such column`, which Hono returned as a bare `Internal Server Error` on `/api/auth/callback`. Dev had the column because `db:reset:dev` drops and rebuilds; prod cannot be reset once it holds accounts, which is exactly when it stops being reachable by the only tool there is. Fixed by hand with `ALTER TABLE identities ADD COLUMN is_admin INTEGER NOT NULL DEFAULT 0`. Every future column needs the same manual ALTER against prod until a real `migrations/` dir exists - `schema.sql` describes a fresh database, never an existing one |
| 2026-09-10 | One `app.onError` boundary answers every unhandled throw with `{error:"server_error", ray}` and logs the message + stack as one JSON line | The row above cost an afternoon precisely because the 500 said nothing: Hono's default answer to a throw is a bare `Internal Server Error` with no request id, no path, and nothing in the log to join against. The cause had to be found by reading source. The ray (`cf-ray`) is the join key - `wrangler tail --env prod --search <ray>` pulls the full line, and a user can quote it in a bug report. `err.message` stays server-side: a D1 error names columns and tables, which is schema disclosure to anyone who can trigger it |
| 2026-09-10 | Traffic goes to Analytics Engine (`to_events`), not the `ANALYTICS_DB` D1 that was bound for it | `schema-analytics.sql` was never applied - both `to-analytics` and `to-analytics-dev` held zero tables, so every pageview would have thrown on a missing table had anything ever called it. Rebuilding it in D1 would have been the wrong fix anyway: D1 is single-threaded per database and bills per row, so a write per pageview serialises behind feed reads and burns the 100k/day free write quota. Analytics Engine is built for the write-many/aggregate-later shape, needs no provisioning (datasets appear on first write), and reads back over SQL at `/accounts/{id}/analytics_engine/sql`. The D1 binding is left in place rather than deleted, with a comment saying why it is not the one to use |
| 2026-09-10 | A person edits their own row through `PATCH /api/people/me` - no id in the path - and email is the one field it refuses | A route taking an id has to prove the caller owns it on every branch, and the branch someone forgets is the vulnerability. The session cookie already names exactly one row, so there is nothing to aim elsewhere. Email is excluded because the address is what the magic link proves ownership of: a PATCH that rewrote it would let anyone holding a borrowed session move the account to their own mailbox and lock the owner out. Changing it has to go back through the mail |
| 2026-09-10 | Handles are validated by `handleProblem()` returning WHICH rule broke, not a boolean, and a UNIQUE violation on the UPDATE answers 409 rather than 500 | The form has to say "3 characters at least" beside the input; a boolean can only produce a generic refusal, and generic refusals get retried identically. The pre-flight SELECT can pass and still lose a race to a signup taking the same handle a millisecond later - the UNIQUE index is the real arbiter, so the catch translates it into the conflict it is. Uppercase is rejected rather than folded so `@Roy` and `@roy` can never be two accounts reading as one, which is the shape impersonation takes |
| 2026-09-10 | Stub-backed unit tests were not accepted as proof the profile routes work; a throwaway probe ran the whole flow against real dev D1 | All 88 tests passed against `stubDb`, whose `run()` does nothing - they prove response shape and say nothing about whether the SQL is valid, whether the UNIQUE index fires, or whether `/api/auth/me` really joins `identities`. The probe minted a session the way a browser does, changed a handle, re-read it on a fresh request, and read the resulting public profile back: 21/21, including 409 on a taken handle and no address anywhere in a populated profile body. `verify.mjs`'s own address check had passed on a 404 with a 21-byte body, which proves a route is wired and nothing about what a real profile withholds |
| 2026-09-10 | `upload_source_maps: true`, and telemetry writes are wrapped so they can never throw | A Worker stack trace otherwise names a line in the minified bundle, which identifies nothing. And analytics is the classic way a working page starts 500ing - `track()` swallows its own errors and is never awaited, so a dataset outage costs a data point rather than the request |
| 2026-09-11 | Use `font-[family-name:var(--font-display)]` (and mono equivalent) for Tailwind font variables. Bare `family-name:--font-display` emitted a literal font-family name and silently fell back to Times, breaking consistency across screens. |
| 2026-09-11 | Sign-in is rate limited by counting rows in D1 (`magic_links`), not by the Workers rate-limiting binding or KV | 5/hour per address, 20/hour per IP. The native binding cannot express an hour: `period` is an enum of exactly `[10, 60]` seconds (`node_modules/wrangler/config-schema.json`), so the longest window it states is a minute - which an attacker paces around trivially, one request every 61 seconds, forever. KV is out for a different reason: one write per second per key is the documented cap, and a counter is one key, so the limiter itself becomes the bottleneck and drops writes under exactly the load it exists for. `magic_links` already stores `email` and `created_at` for every request ever made, so the count is two indexed `COUNT(*)`s over a table we were writing anyway - no new store, no new failure mode. Needed one new column, `ip TEXT`, applied by hand to both remote databases per row 49 |
| 2026-09-11 | Moving a Challenge's `stage` requires being its author or an admin; posting an update body stays open to anyone signed in | `POST /api/challenges/:slug/updates` checked for a session and then never compared the caller to `challenges.author_id`, so any signed-in stranger could push someone else's Challenge to `Learn` - and the lifecycle is the one field that rewrites the object rather than appending to it, so it would read as the author saying so. Splitting the check rather than gating the whole route preserves the product rule that collaboration is open: contributing progress is the point, declaring the thing finished is not. No UI element posts a stage today, so the gate breaks no button |
| 2026-09-11 | Astro's `security.csp` generates the page CSP with per-build script hashes; the Worker sends only what a `<meta>` tag cannot carry | Island hydration ships three inline `<script>` blocks with real bodies, so a hand-written `script-src 'self'` breaks the page outright and a hand-copied hash list goes stale on the next build. Astro recomputes the sha256s each build. The split matters in both directions: `frame-ancestors` is ignored inside a `<meta>` CSP (clickjacking protection would have been silently absent), and the header must NOT restate `script-src` - when two policies apply, each directive is intersected, so a `'self'` in the header would override Astro's hashes and break hydration in the one case that looks most like hardening |
| 2026-09-11 | Source-file safety is a written protocol in `AGENTS.md`, not something the operation lock provides; worktrees belong in `.worktrees/`, never `/tmp` | `coordinate.py` is an flock around build/db/deploy processes and `AGENTS.md` already said it "does not protect source edits" - one line, easy to read past, with no protocol behind it. Nine commits landed between 10:13 and 10:29 from two sessions, three of them hand-rolled rescues ("safety snapshot", "preserve existing seed changes", "parallel session's in-flight work"), so agents were each inventing the rules. Two live hazards had no doc naming them: a worktree detached at `6368907` sitting in `/private/tmp/techno-prod-design-6368907`, where macOS reaping it would take every uncommitted line with no reflog entry since the objects were never written, and a `git stash` that the CLAUDE.md ban should have prevented - harmless once read (105/105 lines, `07:11:16` -> `07:18:03` timestamp churn only) but it cost a line-by-line diff to prove that |
| 2026-09-11 | Challenge illustrations generate on the local $0 model (`local-imagegen`, `x/flux2-klein:4b` on pinned Ollama 0.32.5) - a paid image API needs Roy saying so in the same breath | The first pass reached for OpenRouter `google/gemini-3.1-flash-lite-image` at $0.0336 a call and built an elaborate 2x2-grid-and-slice scheme to cut that to ~$0.10 for nine cards, while `local-imagegen` sat in the sibling folder generating for nothing on hardware already paid for. The grid was real optimisation aimed at the wrong number: it made a paid call cheaper instead of removing it. Note the constraint inverts locally - there is no per-call cost, so the reason to batch a grid disappears and the measured cost becomes time (512x512 median 17.1s over n=30, 1024x1024 37.3s over n=2, read from `/api/model`). `scripts/gen-challenge-art.mjs` defaults to the local backend and requires an explicit `--paid` to spend money, because a rule that lives only in a doc is one a future session reads past |
